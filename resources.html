OpenShift outside Azure (Red Hat)

  • OpenShift and Kubernetes: what's the difference? Kubernetes as the kernel, OpenShift as the distribution, OKD as the community upstream. Use it for the mental model of where OpenShift sits.
  • Usage of oc and kubectl commands. Why kubectl works on OpenShift and what oc adds. The page found is an old version: check the latest version before quoting details.

  • Developer Sandbox for Red Hat OpenShift. Free shared OpenShift cluster with a Red Hat account, used in chapter 7.

Azure Red Hat OpenShift (Microsoft Learn)

  • What is Azure Red Hat OpenShift? Jointly engineered and operated by Microsoft and Red Hat, two architectures (standard and hosted control planes). Use it for the service definition.
  • Responsibility matrix (standard architecture). Who owns what between the customer, Microsoft and Red Hat.
  • Support policy (standard architecture). Hard rules: 3 control plane and 3 worker nodes minimum, 250 workers maximum, supported VM sizes, operators that must stay managed.
  • Service definitions. Regions, node counts and what the customer pays for.
  • Quickstart: create a cluster. Prerequisites: 44 cores at install time, resource providers, permissions, optional pull secret.
  • Azure Red Hat OpenShift pricing. Licence charged per worker vCPU on top of the VMs.
  • Network concepts. Load balancers, Private Link for site reliability engineering access, NSG, egress.
  • Understand managed identities in ARO. One managed identity per core operator plus a cluster identity.
  • ARO with hosted control planes. Node pools and az aro hcp. Preview status may change.
  • Training module: Introduction to Azure Red Hat OpenShift. Short beginner module with an assessment.

ARO compared with AKS

  • Comparing AKS with other Azure container options. Positions ARO as the fit when the organisation already uses OpenShift.
  • Choose an Azure container service. Service models, AKS Standard and AKS Automatic.
  • Choose a compute option for microservices. AKS offers Dapr and KEDA as managed add-ons, while on OpenShift you install and maintain them yourself.
