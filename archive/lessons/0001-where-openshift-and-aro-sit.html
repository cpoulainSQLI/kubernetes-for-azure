Where OpenShift and ARO sit

Before you touch a client cluster, you need one picture in your head: what is plain Kubernetes, what OpenShift adds, and what Azure adds on top. By the end of this lesson you will have logged in to a real OpenShift cluster and seen the difference yourself.

Before reading, make a guess

You log in to an OpenShift cluster with oc, then run kubectl get routes. Routes are an OpenShift-only object. Does the command work or fail? Write your guess down. You will check it in the exercise.

Kubernetes is the kernel, OpenShift is a distribution

Red Hat describes Kubernetes the way you would describe the Linux kernel: a core that many products ship, each with its own patches and tooling around it. OpenShift is one of those products, a distribution of Kubernetes, in the same way Fedora or RHEL are distributions of Linux.1

The chain has three links. Kubernetes is one of the upstream projects of OKD, the community distribution (formerly called Origin). Red Hat then packages OKD with operators and other components into the supported product, OpenShift Container Platform.1 When people say "OpenShift" at a client, they nearly always mean that product.

What OpenShift adds to Kubernetes

You already know pods, deployments and services. They all exist unchanged on OpenShift. What changes is everything around them.

  • The nodes run Red Hat Enterprise Linux CoreOS (RHCOS), an operating system built only to run OpenShift, with CRI-O as the container runtime.2
  • The platform manages itself through operators. The Cluster Version Operator and the Machine Config Operator handle upgrades of the control plane and of the node operating systems, so nobody patches nodes by hand.2
  • There are extra API objects that build on Kubernetes primitives, for example Routes, BuildConfigs and ImageStreams, plus projects, which map namespaces to authenticated users.3
  • It ships a web console and its own CLI, oc.2

Because OpenShift is a certified Kubernetes distribution, kubectl still works against it. oc does everything kubectl does and adds commands such as oc login, oc new-project and oc new-app.3

Two facts about ARO go with this picture. It is jointly engineered, operated and supported by Microsoft and Red Hat, and the clusters live in your own subscription.4 It also comes in two architectures. In the standard one, the control plane runs on dedicated nodes inside your subscription. In the hosted control planes one (built on the HyperShift project, in preview at the time of writing), Microsoft and Red Hat host the control plane and only the workers run in your subscription.4

On Microsoft's side, AKS and ARO are listed as two separate managed Kubernetes offers.5 One concrete difference you will meet early: AKS provides KEDA and Dapr as managed add-ons, while on OpenShift you install and maintain them yourself.7

Why this matters for your mission: on a client ARO cluster, anything you learnt on plain Kubernetes still applies. The new things you have to learn are the red layers. The teal layer is about who does what, and that is what the client will ask you about.

In Red Hat's own framing, how do Kubernetes and OpenShift relate?

Red Hat compares Kubernetes to the Linux kernel and OpenShift to a distribution built around it. OpenShift contains Kubernetes, it does not replace or plug into it.

What is OKD?

OKD (formerly Origin) is the community distribution. Red Hat packages it with operators and other components into OpenShift Container Platform. The node OS is RHCOS, the CLI is oc, the Azure offer is ARO.

After oc login, you run kubectl get routes. What happens?

The OpenShift objects live in the cluster's API server, not in the client. Any Kubernetes client can list them, as long as your permissions allow it. You will verify this in the exercise.

In OpenShift 4, how do the node operating systems get updated?

The Machine Config Operator and the Cluster Version Operator manage the nodes and the control plane. This is one of the main things OpenShift adds over a do-it-yourself Kubernetes.

Which statement about AKS is accurate?

Microsoft lists AKS and ARO as two separate managed Kubernetes offers. AKS has no OpenShift layer, which is exactly why the two are worth comparing.

Exercise: see it on a real cluster

About 20 minutes. You need a Red Hat account and a phone number for verification. The Developer Sandbox gives you 30 days of free access to a shared OpenShift cluster run by Red Hat.6 It is not ARO, but everything in the red layers is the same.

  1. Open the Developer Sandbox, sign in and start your sandbox. Launch OpenShift and you land in the web console.

  2. Install oc. The console links to the download from its help menu (the question mark icon), under Command line tools. Check it with oc version. You probably already have kubectl, any recent version will do.

  3. In the console, open your user menu (top right), choose Copy login command, then Display token. Run the oc login --token=... --server=... line it shows you. The token is a credential: keep it out of chats, tickets and screenshots.

  4. For each command, write your prediction first, then run it.

    oc whoami
oc project
kubectl get pods
oc api-resources --api-group=route.openshift.io
kubectl api-resources --api-group=route.openshift.io
    What you should see

    oc whoami prints your sandbox user name. oc project prints the project the sandbox created for you. kubectl get pods works without any extra setup, because oc login wrote your credentials to the same kubeconfig file that kubectl reads. It may say no resources were found, that is fine.

    The two api-resources commands print the same thing: the routes resource in the route.openshift.io group. The OpenShift objects belong to the server, so both clients see them. Compare with the guess you made at the top of the page.

  5. In one or two sentences, tell your teacher (the agent) what surprised you, or paste any error you got. That closes the feedback loop for this lesson.
