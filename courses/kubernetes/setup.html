Setup

Every lab of this course runs on your own computer, in a Linux shell with Docker Engine, kind, kubectl and a small registry. One command builds that environment for you. This page explains what it creates on Windows and on Linux, then has you run it and check that everything is ready. Read the Introduction first.

What you will have at the end

  • You have a clone of the lab kit on your computer.
  • You have the environment of the course. On Windows it is a WSL distribution named kubernetes-labs, kept for the course. On Linux it is your machine.
  • The environment has Docker Engine, kind and kubectl at the versions the course pins, and a registry that answers on localhost:5001.
  • The readiness report shows no [FAIL].

Before you start

Use the picker at the top of the page to choose your computer. The steps that differ show the right variant.

  • You need Windows 11, or Windows 10 version 2004 or later, with WSL 2. If wsl --status fails in PowerShell, install WSL once from a PowerShell window opened with "Run as administrator", with wsl --install --no-distribution, then restart Windows. Without --no-distribution, that command also installs an Ubuntu distribution that the course does not use. This is the only step that needs administrator rights. How to install Linux on Windows with WSL, Basic commands for WSL
  • If WSL is already installed, bring it up to date with wsl --update. An old WSL may not know the options that course up uses. Which version is the oldest that works is not verified.
  • You need Git to clone the kit. Install Git for Windows
  • You need about 10 GB of free disk space. After the first two labs, the distribution took 8 GB on the computer where the course was tested.
  • The computer must reach the Ubuntu archive, download.docker.com, pkgs.k8s.io, GitHub and Docker Hub. An office proxy may block some of them, and this case is not tested yet.
  • On Ubuntu or Debian, with sudo rights, ./course up installs the tools. On another distribution, install them yourself first: Docker Engine, kind and kubectl at the versions the course pins, plus git, curl, jq, Python 3 and its YAML module. Then ./course up checks them. Linux is not tested yet.
  • You need Git to clone the kit.
  • You need about 10 GB of free disk space for the images and the cluster.
  • macOS is not tested yet. ./course up installs nothing on a Mac. Install a Docker engine, kind, kubectl, git, curl, jq, Python 3 and its YAML module yourself, then ./course up checks them and creates the registry.
  • You need Git to clone the kit.

Get the kit

Clone the lab kit on your computer, in a folder of your choice. The commands are the same in PowerShell and in bash:

git clone https://github.com/<account>/kubernetes-labs.git
cd kubernetes-labs

Every command of this section and the next runs from that folder. On Windows, the WSL distribution clones the kit again inside itself, from the same address, so a fork must be public.

Build the environment

Windows blocks scripts by default. This command allows them in the current PowerShell window only. About execution policies

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\course.ps1 up

.\course.ps1 up says what it creates and asks first. Then it:

  1. Writes the instructions for cloud-init in the .cloud-init folder of your Windows profile, and creates the distribution kubernetes-labs from stock Ubuntu with wsl --install --no-launch.
  2. Starts it once. cloud-init creates the Linux user learner, with sudo and no password, runs the install script of the kit, clones the kit into ~/kubernetes-labs and puts the course command on the path (cloud-init file, environment script).
  3. Restarts the distribution once, so that it logs in as learner, then creates the registry.

The first run took about 2 minutes on the computer where the course was tested. A second run only checks, and takes a few seconds. Apart from the cloud-init file in your profile, course up changes nothing on Windows: the distribution has its own Docker Engine.

./course up

./course up lists the tools that are missing or at another version, and what it would install: Docker Engine from the repository of Docker, kubectl from the repository of Kubernetes, kind from its release on GitHub after checking the checksum published with it, and a few small tools. It asks before it installs anything, with sudo, through the install script of the kit. It then creates the registry, and offers to put a course command in ~/.local/bin so that it runs from any folder. Install Docker Engine on Ubuntu, Install kubectl on Linux, kind quick start

When the install script adds you to the docker group, ./course up stops there. Log out and back in, or restart the machine if it is a virtual machine, then run ./course up again to create the registry. Linux post-installation steps for Docker Engine

./course up

On a Mac, ./course up checks Docker, kind and kubectl, creates the registry and reminds you that the path is not tested.

The registry is part of the environment. It keeps the images you push in a Docker volume, so that the labs can pull them. Cleaning a lab never removes it.

Docker Desktop

You do not need Docker Desktop, and the course does not use it. If you have it on Windows, it should be able to stay installed and running, but that is not tested yet. Keep its WSL integration off for kubernetes-labs, in Docker Desktop under Settings, Resources, WSL integration. Docker Desktop turns it on for the default WSL distribution, and whether kubernetes-labs becomes the default when it is your only distribution is not verified. The readiness report warns when the docker command of the distribution reaches Docker Desktop. Docker Desktop WSL 2 backend on Windows

Check that everything is ready

.\course.ps1 check

./course check

The report changes nothing. It prints [PASS], [FAIL] or [WARN] for WSL and the distribution on Windows, the tools and their versions, the registry, the kit and the cluster. Each [FAIL] comes with a hint, most often to run course up again. The version of Docker Engine is printed, not checked: the course works with the current release.

Every session: open, start, work

Open a terminal in the distribution. It starts the distribution if it is stopped. You can also open "kubernetes-labs" from Windows Terminal.

.\course.ps1 connect

Open a terminal. Your machine is the environment, so there is nothing to connect to.

In the environment (bash)

course start 01

On Linux and macOS, course runs from any folder once ./course up has put the launcher in ~/.local/bin, which it offers on Linux only. Without it, run ./course start 01 from the kit folder.

course start NN is the one command to run when you begin a lab and every time you come back to it. It creates what the lab needs, starts what has stopped, and says which task you are on. Your files live in ~/work, outside the kit.

On Windows, the distribution stops by itself a few seconds after its last terminal closes. Your work in ~/work, the registry and your cluster are kept, with everything you applied to it. The next course start NN brings the lab back, and repairs a cluster node that did not come back by itself. .\course.ps1 stop stops the distribution at once. Advanced settings configuration in WSL

Edit files from VS Code

On Windows, VS Code edits the files of the distribution through its WSL extension, which installs a small VS Code server inside the distribution. Install VS Code on Windows with the option that adds it to the path, and the WSL extension. Then, in a terminal of the distribution, code ~/work opens your work folder. This has not been tried with the course yet, and neither has whether an open VS Code window keeps the distribution running. Developing in WSL

Remove the environment

.\course.ps1 destroy

This deletes the distribution kubernetes-labs with everything in it, and your work in ~/work goes with it. Copy what you want to keep first. Windows shows the files of the distribution at \\wsl.localhost\kubernetes-labs. Basic commands for WSL

./course destroy

This removes what belongs to the course: the cluster, the registry with the images you pushed, and the course launcher. It keeps Docker, kind, kubectl and your work in ~/work.
