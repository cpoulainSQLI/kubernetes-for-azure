Introduction

What the course builds, who it is for, how the website and the lab kit fit together, and how a lab works. Read this page before the Setup.

What the course builds

You start with a small web app and build your first container image from it. You run the image, push it to a registry, and then run the same app on a Kubernetes cluster: you deploy it, expose it, scale it, roll out a new version and roll it back. Later chapters add configuration and storage, other kinds of workloads, access control, packaging, and the debugging of an app that does not start.

Every chapter ends with a lab on your own computer. A script checks your work task by task and tells you what to fix. The outline lists the chapters.

Who it is for

You can type commands in a terminal and edit text files. You have never built a container image or used Kubernetes. You do not need to write application code, and you do not need a cloud account: the whole course runs on your computer and costs nothing.

The website and the lab kit

The course lives in two Git repositories.

  • The website is what you are reading. It holds the explanations, the lab tasks and their hints, and the reference solutions explained step by step. You never need a copy of it.
  • The lab kit is the repository kubernetes-labs. It holds what you run: the course command, the scripts that build your environment and that set up and check each lab, the sample app and the files of the reference solutions. You clone it on your computer.

Follow the main branch of the kit. course update brings your clone up to date. Your work is not part of the kit, so an update never changes it.

How a lab works

The labs run in a Linux shell with Docker Engine, kind, kubectl and a small registry. kind runs a whole Kubernetes cluster as a few Docker containers on your computer. On Windows, the shell is a WSL distribution that the course creates and keeps for itself, and kind documents how it runs in WSL 2. On Linux, it is your machine. The Setup page builds it with one command.

Use the picker at the top of the page to choose your computer. Only the commands that build the environment differ between Windows and Linux. The labs themselves always run in the Linux shell.

Every lab follows the same steps. With lab 01 as the example:

  1. course start 01 prepares what the lab needs and copies its starting files to ~/work/01-containers. Run it again whenever you come back: it brings the lab back and tells you which task is next.
  2. You do the tasks of the chapter. They are goals with acceptance criteria, not commands to copy, and each task has two hints that you open when you need them.
  3. course check 01 reads your files and the state of your work, and prints [PASS], [FAIL] or [WARN] for each criterion, with a hint for each failure. --guided follows you task by task, and --deep adds live tests. Without --deep the check never changes anything.
  4. course break 01 puts one fault into your finished lab, and you find and repair it.
  5. course clean 01 removes what the lab created. Your files and the registry stay.

The reference solutions show one way to pass each lab. Look at them after you have tried, not before.

What it costs

Nothing. The course needs no cloud account, and every tool it installs is free. It needs disk space, about 10 GB, and an internet connection to download the tools and the images the first time.

Docker Desktop is not needed. If you already use it, it can stay installed. On Windows, the distribution of the course has its own Docker Engine, apart from Docker Desktop. Docker Desktop is free only for some uses, such as personal use, education and businesses below a size limit, and the course does not depend on it. Docker Desktop license agreement
