Quotas, regions and resource providers

Three limits of an Azure subscription that matter for the courses that run on Azure: Azure Kubernetes Service, Argo CD with AKS, and Azure Red Hat OpenShift. Course 1 runs on your own computer and needs none of this. The Azure courses will check these limits for you before they create anything.

vCPU quotas

Azure limits how many vCPUs (virtual processors) you can run, at two levels in each region: a total for the region, and a limit per VM family. A deployment fails if it would exceed either one. Check vCPU quotas

The big number comes with Azure Red Hat OpenShift: creating a cluster needs at least 44 cores at install time (8 for a temporary bootstrap machine, 24 for the control plane, 12 for the workers), and 36 once the install is done. With the default sizes, those cores come from the DSv5 family. Create an ARO cluster

Credit-based subscriptions often start with a lower limit. You can ask for a higher one in the portal, under Quotas. Increase VM-family vCPU quotas

Regions

Not every region offers every VM size, AKS and ARO, and a subscription can be barred from some sizes in some regions. Each Azure course names the regions it was tested in when it is written.

Resource providers

Each Azure service is delivered by a resource provider, such as Microsoft.Compute for VMs. A subscription must register a provider before it can use it. Registering a provider costs nothing. Resource providers
