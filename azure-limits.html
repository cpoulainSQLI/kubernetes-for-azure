Quotas, regions and resource providers

Three limits of an Azure subscription that the readiness report of the setup, ./course check, checks. None of them stops you before chapter 6. Read this page when the report prints a warning about them, or before you create a cluster in Azure.

vCPU quotas

Azure limits how many vCPUs (virtual processors) you can run, at two levels in each region: a total for the region, and a limit per VM family, such as the DASv5 family of the lab VM. A deployment fails if it would exceed either one. Check vCPU quotas

The lab VM needs 2 vCPUs. The big number comes with chapter 8: creating an ARO cluster needs at least 44 cores at install time (8 for a temporary bootstrap machine, 24 for the control plane, 12 for the workers), and 36 once the install is done. With the default sizes, those cores come from the DSv5 family. Create an ARO cluster

Credit-based subscriptions often start with a lower limit. The readiness report shows this as a warning, not a failure, because nothing before chapter 8 needs it. You can ask for a higher limit in the portal, under Quotas. Increase VM-family vCPU quotas

the readiness report warns that your regional vCPU limit is 20. Can you go on with chapter 1?

Yes. Chapters 1 to 7 need far fewer vCPUs. Before chapter 8, request a higher limit, and read that chapter's notes on what to do if a credit-based subscription cannot get it.

Regions

The default region of the course is Sweden Central. In November 2026 it was the cheapest of four European regions compared for the lab VM size, and it offers AKS and ARO. The region is a setting in .env, and the readiness report checks that your region offers the VM size, AKS and ARO for your subscription.

Resource providers

Each Azure service is delivered by a resource provider, such as Microsoft.Compute for VMs. A subscription must register a provider before it can use it. course up registers every provider the course uses, which costs nothing. Resource providers
